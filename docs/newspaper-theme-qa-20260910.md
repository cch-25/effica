# 한국 종이신문 UI 개편

## 디자인 기준

조선일보와 동아일보의 지면 안내 및 공개 지면 미리보기를 참고했다. 신문사의 로고나 기사 이미지를 서비스 자산으로 복제하지 않았다.

- 조선일보 전용 서체: https://event.chosun.com/100/100font.html
- 조선일보 지면 구성과 단 규격: https://about.chosun.com/mobile/pages/ad_info_02_01.php
- 조선일보 실제 지면 사례: https://reprint.chosun.com/
- 동아일보 면별 구성과 1면 미리보기: https://www.donga.com/news/Pdf

완전한 흰색 배경과 먹색 활자를 기본으로 제호, 면 정보, 단 구분선, 기사 제목의 위계를 구성했다. 화면을 장식하는 입체 구와 색면을 제거했다. 의미가 있는 기사 관점 그래프의 선택과 회전 기능은 유지했다. 위치와 선의 형태, 명도 차이로 정보를 구분한다.

## 적용 범위

| 화면 | 구성 |
| --- | --- |
| 종합 1면 | 주요 이슈, 출처별 기사, 실제 추천 기사 분포, 독자 안내를 비대칭 단으로 배치 |
| 이슈 목록 | 중요 기사 목록과 분야별 지면을 분리 |
| 이슈 비교 | 공통 사실과 언론사별 기사를 대조하는 다단 지면 |
| 기사 상세 | 본문, 분석 주석, 독자 평가란 |
| 관점 지도 | 흑백 좌표도, 분포 도표, 기사 목록 |
| 활동 기록 | 통계 띠, 독자 기록지, 활동 원장 |
| 로그인과 온보딩 | 공통 제호 아래 신청서와 설문지 |
| 개인정보 관리 | 독자 안내와 신청 항목, 확인 대화상자 |
| 공유 | 미리보기, 생성 상태, 공개 페이지, 다운로드 PNG |
| 관리자 | 지면 목차와 공통 제호, 운영 기록과 관리 양식 |
| 오류와 빈 화면 | 공통 활자와 안내 형식, 전용 404 안내 |

모바일은 주요 기사를 먼저 읽고 보조 도표와 해설을 이어 읽도록 배치한다. 작은 화면에서는 기사 열을 줄이고 하단에 글자 중심 탐색을 제공한다. 관리자 화면도 고정 사이드바 대신 제호 아래 지면 목차를 두며, 모바일에서는 목차와 운영 양식을 좁은 너비에 맞게 재배치한다.

## 서체

조선일보 공식 배포처에서 조선신명조와 조선굵은명조를 직접 내려받았다. 전체 글리프를 유지한 WOFF2를 `next/font/local`의 400과 700 두 굵기로 제공한다. 공유 이미지 렌더러도 같은 공식 ZIP의 원본 TTF 두 파일을 사용한다. 배포 조건은 두 자산 폴더의 LICENSE 파일에 보관했다. 브라우저는 외부 폰트 CDN에 접속하지 않는다.

## 검증

확인 대상은 33개 경로다. 기사와 이슈의 동적 경로, 공유 카드의 다섯 상태, 관리자 10개 메뉴를 포함한다. 320px, 390px, 768px, 1440px에서 총 132개 화면을 캡처했다. 변경 후 재검사한 결과는 동일한 경로와 뷰포트 기록을 갱신한다.

- 화면 검사: 모든 기록에서 가로 넘침 0건. 실행 중 JavaScript 오류 0건. 검사한 텍스트와 배경의 유색 요소 0건.
- 브라우저 기능: 기존 34개 사용자 여정 확인. 제호 링크 변경에 따른 키보드 탐색 선택자를 갱신하고 해당 검사 재통과.
- 접근성: 핵심 페이지 68개 검사 통과. 활성화 시점의 버튼 색 전환을 제거해 중간 상태에서도 대비를 유지.
- 프론트 단위 및 컴포넌트 검사: 91개 통과.
- 공유 이미지와 관련 API 검사: 24개 통과.
- TypeScript, ESLint, 변경된 Python 파일 Ruff, Next.js 운영용 빌드 확인.
- 필터 드로어, 선택 메뉴, 모바일 확인창을 실제로 열어 캡처와 배치를 확인.
- 공유 PNG는 검사 완료 상태와 미실시 상태를 별도로 렌더링해 확인.

로컬 화면 증거와 검사 결과는 `output/playwright/newspaper/`에 있다. 전체 검사 결과는 `audit.json`, 화면은 뷰포트와 경로 이름을 가진 PNG다. `client/scripts/newspaper-audit.mjs`가 화면 검사를 재현한다. 실행과 검증은 머신의 `.ops/run.sh`를 이용했다.

브라우저 시나리오는 mock API를 사용했다. 이는 운영 DB 검증이나 배포 완료를 의미하지 않는다. 기존에 저장된 공유 이미지 파일은 자동으로 다시 쓰지 않으며 새로 생성하는 이미지부터 새 서체와 디자인을 사용한다.


## 동아일보 첨부 지면을 반영한 두 번째 개편

사용자가 첨부한 동아일보 1면의 제호와 좁은 기사 단, 머리기사 옆 넓은 도판을 참고했다. 이미지 속 광고나 기사의 문구는 서비스 내용으로 가져오지 않았다.

- 모든 페이지의 문서 바탕과 팝업은 `#ffffff`다. 도표 캔버스와 새로 생성하는 공유 PNG도 흰색으로 변경했다.
- 제호의 높이와 탐색 영역의 여백을 줄이고, 날짜와 판 정보를 얇은 가로선 사이에 배치했다.
- 종합면은 3:4 비율의 머리기사와 자료 도판, 세 출처의 좁은 기사 단, 다른 주제의 짧은 기사로 구성했다. 추천 기사는 데스크톱에서 5단, 모바일에서 2단으로 읽는다.
- 기사 요약은 이슈별 기사 API에서 가져온다. 기존 추천 순서와 분석값을 유지하며, 요약 요청 실패 시 이미 확보한 제목과 메타데이터를 그대로 제공한다.
- 자료 도판은 공개 분석이 있는 추천 기사 중 최대 12건의 편향성과 과장성을 표시한다. 두 값 중 과장성이 공개되지 않은 기사는 도판에서 제외한다. 가까운 점의 번호는 연결선으로 구분한다. 원본 기사 사진 필드는 현재 데이터에 없어 임의의 사진을 넣지 않았다.
- 이슈 목록은 주요 이슈와 주제별 지면으로 나누었다. 비교 지면과 기사 상세는 공통 사실, 분석 주석, 독자 평가란을 구분선으로 묶었다.
- 설문은 데스크톱에서 두 단의 인쇄 응답란으로 구성했다. 모바일에서는 질문 순서대로 한 단으로 읽는다. 선택 상태와 키보드 조작을 유지했다.
- 관리자 10개 메뉴는 제호 아래 목차로 바꾸고 관리 목록을 원장처럼 배치했다. 고정 사이드바와 둥근 운영 스위치를 제거했다.

재검증 결과: 33개 경로를 네 가지 너비로 캡처한 132개 화면 모두 문서 배경 RGB가 `(255, 255, 255)`였다. 가로 넘침과 JavaScript 실행 오류는 없었다. 사용자 여정 34개, 접근성 68개, 프론트 단위 및 컴포넌트 91개, 공유 이미지 검사 2개가 통과했다. TypeScript와 ESLint, Next.js 운영용 빌드도 확인했다. 필터 드로어와 선택 메뉴는 실제로 열어 데스크톱과 모바일 화면을 확인했다.

이번 개편 역시 mock API 기반의 로컬 검증이며 운영 배포는 포함하지 않는다. 기존에 저장된 공유 PNG는 자동으로 바뀌지 않는다.


서체 로딩 추가 검증: 기존 조선일보명조 파일은 브라우저가 vhea 테이블을 거부해 대체 서체로 표시되는 문제가 있었다. 공식 업그레이드 파일에도 동일한 테이블 버전이 있어, 파일을 수정하지 않고 같은 공식 배포처의 조선신명조와 조선굵은명조로 교체했다. 이제 `document.fonts.load()`로 실제 한글 및 영문 표본의 본문과 굵은 서체가 모두 `loaded`인지 검사한다. 단순한 CSS font-family 값만으로 적용 성공을 판단하지 않는다.

최종 서체 검사에서는 132개 화면 모두 본문과 제목용 서체가 실제로 로드됐고, 흰색 문서 배경과 가로 넘침 0건을 함께 확인했다. 서체 교체 후 접근성 68개 및 공유 이미지 2개 검사를 다시 통과했다.
