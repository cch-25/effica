## 운영 검사에서 추가로 수정한 문제

- 마이그레이션 ID를 MariaDB의 32자 제한에 맞췄다. 최초 배포 실패 후 기존 DB와 릴리스 복구를 확인한 다음 재배포했다. 현재 revision은 `0020_questionnaire_beta`다.
- 조선일보의 정상적인 경로 끝 `/` 리다이렉트가 반복되는 문제를 수정했다. HTTP 요청 경로와 저장용 URL 정규화를 분리했다.
- 사용자 요청인 내보내기, 공유 이미지 생성, 계정 삭제가 뉴스 수집 작업보다 먼저 처리되도록 했다. 이미 등록된 낮은 우선순위 작업에도 적용된다.
- 내보내기에서 존재하지 않는 `users.updated_at`을 조회하지 않도록 하고, 동의 상태는 `withdrawn_at`으로 계산하도록 수정했다.
- 설문 저장 후 탭 사이에 변경 시각만 알리고 프로필을 다시 조회하도록 했다. 브라우저 알림이나 저장소에 설문 답변 원문을 넣지 않는다.

## 운영 환경 검증

전용 합성 계정을 사용해 기존 회원 데이터와 분리해서 검사했다.

- 공개 서비스의 API가 MariaDB를 사용하며 준비 상태와 DB revision이 일치함을 확인했다.
- 현재 동의 2개와 베타 검사 30문항 응답을 저장했다. 중립 응답은 (0,0,0)으로 계산됐다.
- 평가 생성 시 +10, 수정 시 +0을 확인했다. 수정과 삭제 뒤에도 크레딧 지급 기록은 한 건이었다.
- 내보내기 요청부터 worker 처리와 실제 다운로드까지 성공했다. 13개 데이터 구역과 본인 설문 및 평가 기록을 확인했으며 인증 비밀 필드는 없었다.
- 운영 화면의 다운로드 링크로 JSON 파일을 실제 내려받았다.
- 공유 PNG를 생성해 한글 표시와 1200×1000 크기를 확인했다. 폐기한 공개 링크는 404를 반환했다.
- 브라우저에서 30문항 응답과 이전 단계 답변 보존을 확인했다. 별도 탭 저장 후 원래 카드가 새로고침 없이 경제 좌표 0에서 -10으로 갱신됐다.
- 운영 화면에서 첫 평가의 10크레딧 알림과 수정 메시지를 확인했다. 기사 평가 수정 후에도 설문 좌표 -10은 유지됐다.
- 과장성 도움말이 클릭 즉시 표시됐다. 분석 대기 기사에는 일일 제한과 한국 시간 기준 다음 처리 가능 시각이 표시됐다.
- 모바일 390px에서 공유 카드 화면에 가로 넘침이 없었다.
- 검증 계정 두 개는 계정 삭제 API와 worker 처리를 통해 정리했다. 활성 세션과 공개 카드는 0개다.

## 해석과 운영 범위

소비 다양성은 공개 분석이 있는 서로 다른 소비 기사를 세 구간으로 분류해 균형과 최대
12개까지의 기록 수를 반영한다. 반복 읽기나 평가는 한 번만 계산한다. 개인이 매긴 평가
점수는 다양성 분류나 자신의 이념 좌표 계산에 사용하지 않는다.

이념 검사는 사용자가 운영 적용을 승인한 `2.0-beta`다. 정식 검증된 진단 도구라는 주장을
하지 않는다. 이전 행동 프로필이나 다른 검사 버전을 현재 결과로 혼용하지 않는다.
공개 카드에는 계정 식별자, 크레딧 내역이나 설문 답변 원문을 노출하지 않는다.
공개 독자 집계는 참여자가 5명 미만일 때 축별 수치를 반환하지 않는다.

새 출처에서 기사를 수집한 사실과 AI 분석 또는 공개 이슈 완성은 별도로 확인한다.
일일 분석량 제한과 LLM 중복 요청 방지 정책은 유지했다. 응답이 확인되지 않은 기존 제출
요청을 재실행하지 않았다. 공개 이슈는 필요한 출처와 최신 분석 조건을 충족한 후 표시된다.
