검증일은 2026-09-10이다. 아래 구현은 로컬 변경 기준이며 운영 배포 완료를 뜻하지 않는다.

## 소비 다양성과 개인정보

다양성은 공개 분석이 있는 서로 다른 소비 기사만 센다. 기사의 공개 편향 점수를
좌측, 중앙(-10~10), 우측의 세 구간으로 나누고 구간 균형과 12개까지의 기록 수를 반영한다.
같은 기사에 대한 반복 읽기와 평가는 한 번만 계산한다. 사용자가 기사에 매긴 개인 점수는
다양성 분류나 정치 이념을 계산하는 입력으로 사용하지 않는다.

개인의 이념 좌표는 현재 버전 검사 응답에서만 나온다. 이전 행동 프로필과 이전 검사 버전은
개인화, 시각화, 타임라인, 공유 결과에서 제외한다. 검사는 선택 사항이며 건너뛸 수 있다.
로그인은 필요한 동의 여부만 확인하고 검사 미실시를 이유로 원래 이동 경로를 막지 않는다.
이전 방식의 공유 카드는 새 카드 생성을
안내하며 기존 이미지를 직접 요청해도 반환하지 않는다. 공개 카드에는 계정 식별자나 크레딧
내역 대신 소비 집계와 공개에 동의한 검사 결과만 포함한다.
공개 독자 집계는 참여자가 5명 미만이면 축별 수치를 반환하지 않는다. 저장된 공유 데이터에
개인정보가 섞여 있어도 허용된 집계와 검사 필드만 공개 응답에 포함한다.

## 검증 근거

- 서버 및 통합 테스트 340개 통과, Python 정적 검사 통과
- 프런트 단위 테스트 91개 통과, ESLint와 TypeScript 및 운영용 빌드 통과
- 브라우저 시나리오 34개와 실제 API 연동 검사 6개 통과
- 브라우저에서 30문항 응답과 이전 단계 답변 보존, 카드 복귀 및 결과 갱신 확인
- 브라우저에서 첫 평가 크레딧과 수정 메시지 확인
- 브라우저에서 내보내기 요청 후 새로고침해도 준비 상태가 유지되는지 확인
- 모바일 390px에서 가로 넘침 없음 확인
- 카드 및 설문 화면의 axe 접근성 검사 위반 없음 확인
- 한글 PNG의 검사 완료와 미실시 상태 렌더링 확인
- 배포 사전 검사 통과

브라우저 `real` 검사는 memory backend와 연결된 로컬 통합 검사다. 운영 MariaDB의 변경이나
실제 서비스 배포를 증명하지 않는다. MariaDB 통합 검사는 별도 테스트 DB 설정이 없어 실행하지
않았다. 전체 실행에서 테스트 9개가 제외됐으며, 그중 8개는 MariaDB 전용 검사이고 1개는
별도 실행이 필요한 실시간 언론사 연결 검사다. 실시간 언론사 검사는 별도 실행에서 통과했다.
운영 서비스 상태 점검은 읽기 전용으로 수행했다.

## 운영 반영 전 확인

1. DB 백업과 `0020_questionnaire_beta` migration을 적용한 뒤 API와 worker를 배포한다.
2. 변경된 API가 준비된 뒤 프런트를 배포한다.
3. 출처 부트스트랩은 먼저 드라이런으로 확인한다. 승인 조건과 명령은
   [출처별 근거 문서](source-coverage-qa-20260910.md)에 정리했다.
4. 기존 뉴시스 승인 기록은 서면 허가 근거를 확인한다. 새 코드가 기존 운영 DB의 승인 상태를
   자동으로 덮어쓰지는 않는다.
5. 실제 계정으로 검사, 평가, 내보내기 및 공유 이미지 다운로드를 확인한다. 상태 API 응답과
   worker의 다음 수집 실행도 확인한다.

2026-09-10 운영 조회 당시 API와 worker는 동작 중이었다. 주요 EVENT 이슈가 없는 상태는
출처 부족과 공개 조건에 관련돼 있었으며, 분석 작업에는 일일 선택과 처리량 제한이 적용돼
있었다. 다음 처리 가능 시각을 작업 완료 시각으로 간주하지 않았다. 응답이 확인되지 않은
LLM 요청은 중복 과금 가능성이 있어 재실행하지 않았다.
