# 이슈 중심 뉴스 수집 요구사항

## 제품 범위

에피카는 정치적 입장과 보도 관점을 비교할 수 있는 쟁점만 다룬다. 공개 분류는 정치, 경제, 사회 세 가지다. 국내 정치와 밀접한 사안을 우선한다. 경제와 사회 및 국제 사안은 정책이나 공적 의사결정에 관한 실질적인 입장 충돌이 있을 때 포함한다.

스포츠 경기 결과, 연예 소식, 행사 안내, 단순 시세, 기업 홍보와 단순 사건 전달은 제외한다. 논쟁을 인위적으로 만들거나 언론사의 정치 성향만으로 쟁점성을 인정하지 않는다.

## 수집과 선정

1. 한국시간 날짜마다 워커가 `discover_issues` 작업을 한 번 생성한다. 실행 중인 워커의 첫 점검에서 시작하며 특정 시각의 외부 cron은 필요하지 않다. 재시작이나 여러 워커의 동시 실행은 동일한 날짜 키를 공유한다.
2. LLM이 실제 웹 검색을 통해 이슈 후보를 먼저 발굴한다. 최근 3일을 우선하고 최대 7일까지 확장한다. 기본 후보 수는 10개이며 최대 12개로 제한한다. 후보에 실제 검색에서 확인된 원문 URL을 연결하고, 승인된 독립 언론사 3곳 이상에서 다뤄진 후보를 먼저 검증한다. 이 단계의 기사 URL도 이후 본문 확보에 사용한다. 단일 기사에 등장한 세부 주제를 주요 이슈로 부풀리지 않는다.
3. 각 후보를 다시 검색해 다양한 언론사의 원문 URL을 찾는다. 원문 검색에는 수집 승인된 언론사 도메인을 검색 도구의 필터로 전달한다. 검색 도구가 반환한 근거에 실제로 존재하는 URL만 수집 대상으로 인정한다.
   기본 검색과 원문 확보가 정상 종료됐지만 독립 언론사 3곳에 미달하면, 루트 `TAVILY_API_KEY`가 설정된 경우 Tavily `news` 검색으로 후보를 한 번 보충한다. `advanced` 검색과 승인 도메인 필터를 고정하고 자동 매개변수 변경을 끈다. 기본 검색의 최대 15개 URL에 보충 검색 최대 15개를 추가로 확인하며 이미 시도한 URL은 다시 가져오지 않는다. 검색 API 오류나 불명확한 기본 검색 응답은 보충 검색을 시작하는 조건이 아니다. 기본 검색에서 이미 3곳을 확보하면 Tavily를 호출하지 않는다. 보충 결과에도 동일한 원문 검증과 사건 관련성 선정을 적용한다.
4. 등록된 수집 승인 상태와 원문 접근 가능 여부를 확인한다. 기사 제목과 본문 및 발행일은 실제 언론사 페이지에서 가져온다. 검색 요약이나 LLM이 작성한 텍스트를 기사 본문으로 저장하지 않는다.
5. 확보한 본문을 근거로 같은 사건과 정책 쟁점을 다루는 기사인지 재검증한다. 같은 키워드가 포함되었다는 이유로 서로 다른 사건을 합치지 않는다.
6. 독립적인 언론사 도메인 3곳 이상을 확보한 이슈만 발행한다. 한 언론사의 모바일과 서브도메인 또는 여러 source 레코드는 한 출처로 계산한다. 날짜가 없거나 미래이거나 7일보다 오래된 기사는 제외한다.
7. 국내 정치적 중요성과 쟁점성 및 보도량을 고려하여 최대 5개를 발행한다. 목표는 3~5개지만 충분한 근거가 없으면 더 적게 발행한다. 관련 없는 기사를 채워 넣지 않는다.
8. 이슈당 독립 언론사의 기사 3~5개를 기본으로 선정한다. 6~8번째 기사는 앞선 기사에 없는 구체적인 쟁점과 본문 근거가 있을 때만 포함한다. URL별 추가 맥락을 결과에 기록하며 같은 이유의 반복으로 숫자를 늘리지 않는다. 최대 5개 이슈가 확보되면 추가 후보 탐색을 중단한다.

## 공개 화면과 분석

- 주요 이슈와 이슈 비교는 위 과정을 통과한 사건 단위의 이슈를 사용한다.
- 추천 기사, 주제별 탐색과 기사 상세 등 공개 조회는 발행된 이슈에 속하는 기사만 제공한다.
- 편향 분석은 확보한 모든 이슈 기사에 연결한다. 이슈 비교 분석에는 서로 다른 언론사 최소 3곳의 기사를 사용한다.
- 분석이 진행 중인 상태와 완료된 상태를 구분한다. 기사 확보만으로 분석 완료를 표시하지 않는다.
- 새 이슈가 정상 저장되면 먼저 배치하고, 5개보다 적으면 이전 발행 목록에서 아직 유효한 이슈로 빈자리를 채운다. 유효성은 승인된 독립 언론사 3곳 이상의 현재 원문과 7일 기간으로 재검사한다. 이전 이슈끼리는 기존 편집 우선순위를 따른다. 총 5개 밖의 이슈는 공개 대상에서 제외한다.
- 이어 보여주는 기존 이슈의 최초 발행 시각과 최신 보도 시각, 버전과 검수 날짜를 오늘 값으로 바꾸지 않는다. 필요한 미완료 분석과 유효한 비교 구성은 중복 방지 정책 안에서 다시 예약한다. 실패하거나 검증된 새 이슈가 없으면 이전 목록을 갱신하지 않는다. 7일 유효기간은 계속 적용된다.
- 과거 데이터의 공개 제외와 물리적 삭제는 구분한다. 기존 7일 보관 및 최대 300기사 보관 정책을 유지하되 현재 발행 이슈의 유효한 기사를 먼저 보존하고 이전 묶음부터 정리한다. 사용자 기록과 참조 무결성을 보존한다.

## 운영과 실패 처리

기존 전체 언론사 피드의 6시간 자동 순환 수집은 운영 워커에서 일일 이슈 발굴로 교체한다. 이미 대기 중인 과거 자동 수집 작업은 건너뛴다. 기존 수동 수집 도구는 유지하지만 수동으로 저장한 기사나 기존 유사도 군집은 일일 큐레이션 표식을 받을 수 없다.

검색 요청도 기존 하루 5달러 상한의 내역에 포함한다. 검색 도구 비용과 토큰 비용을 요청 전에 예약한다. 응답이 불명확한 유료 호출은 자동 재호출하지 않는다. 완료된 응답은 요청 키로 재사용한다.

Tavily 보충 검색도 같은 `discovery` 비용 원장과 전체 요청 한도를 사용한다. 무료 크레딧 유무와 관계없이 요청 전 2크레딧의 종량제 상당액인 $0.016을 예약한다. 날짜와 이슈 및 승인 도메인으로 요청을 식별하고 완료된 URL 목록을 재사용한다. 실패한 호출은 자동 재시도하지 않는다. 기사 분석을 위한 보호 예산은 기존과 동일하다. 이 보충 기능에는 추가 DB 마이그레이션이 필요하지 않다. 도입 근거와 한계는 [한국 정치 이슈 검색 비교](tavily-korean-search-evaluation-20260911.md)에 기록한다.

검색과 후보 검증은 기사 분석에 필요한 몫을 남기는 범위에서만 허용한다. 일일 비용 상한의 20%와 기본 분석 요청 30회분을 보호하며, 작은 요청 상한에서는 요청 몫을 60%로 축소한다. 비용을 고정 60%로 묶어 두던 정책은 실제 원문 확보를 막아 20%로 조정했다. 요청 30회는 하루 총 분석 배정량이므로 오늘 이미 예약한 기사 분석과 비교 요청을 빼고 아직 사용하지 않은 몫만 남긴다. 이미 확보한 이슈와 현재 검증할 기사들의 보수적 분석 비용 추정 또는 요청 수가 더 크면 그 값을 적용한다. 남은 기사 분석 한도와 전체 요청 한도에 맞춰 이슈의 기사 수를 줄이고, 독립 언론사 3곳을 처리할 한도도 없으면 추가 후보 검색을 중단한다. 기본 $5 설정에서는 최소 $1와 실제 분석 비용 추정 중 큰 금액을 남긴다. 이 보호는 기존 잠금 내에서 검사하고 한도를 추가 지출하지 않는다. 비용 예약은 실제 청구액이 아니며 반환하지 않는 보수적 계산이다. 분석 100개, 비교 10회, 전체 요청 110회 및 $5 상한은 유지한다.

일일 발굴의 완료 기록에는 실제 저장된 발행 이슈 수와 후보 수, 거절 사유 및 중단 이유를 남긴다. 선정한 후보라도 저장 단계에서 발행되지 않으면 발행 수에 포함하지 않는다. 발행된 이슈가 없으면 `NO_ISSUES_PUBLISHED`로 기록한다. 삭제 기록이 있는 기사는 원문 검증 단계부터 제외해 출처 수를 부풀리지 않고 불필요한 선정 비용을 쓰지 않는다. 원문 페이지의 대표 이미지 URL은 기사 메타데이터로 저장하고 출처와 함께 표시하며, 이미지가 없거나 불러오지 못하면 사진 영역을 표시하지 않는다. 이미지 메타데이터에는 `0023_article_images` 마이그레이션이 필요하다.

신규 환경에는 `0022_issue_discovery_budget` 마이그레이션이 필요하다. 운영 DB 마이그레이션과 배포는 별도 운영 명령으로 수행한다. 검색 API 자격증명과 지원 모델 및 서로 다른 언론사 3곳 이상의 실제 수집 승인 상태가 있어야 정상 발행할 수 있다. 기본 카탈로그의 존재는 수집 승인을 의미하지 않으며 승인 부족과 원문 확보 실패는 작업 결과에 기록한다.

## 인수 기준

- 정치, 경제, 사회 이외의 탐색 분류가 표시되지 않는다.
- 서로 다른 3개 언론사의 실제 기사 없이 주요 이슈를 발행하지 않는다.
- 중복 source ID, 모바일 도메인과 미래 발행일로 발행 조건을 우회할 수 없다.
- 기사 검색 결과는 검증한 사건에 직접 귀속되고 기존 키워드 군집으로 다시 섞이지 않는다.
- 같은 한국시간 날짜에 워커를 재실행해도 새 검색 작업을 생성하지 않는다.
- 검색 실패와 예산 부족 및 출처 부족 시 관련 없는 기사를 노출하지 않는다.
- 단위 검증과 메모리 기반 브라우저 검증을 실제 운영 발행 성공으로 보고하지 않는다.
