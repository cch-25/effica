서버 검증에는 실제 HTML 파서를 사용한 HTTP mock transport 기반 검색 경로가 포함된다. 날짜별 작업 중복, 검색 근거에 없는 URL, 언론사 중복과 수집 승인 상태 및 원문 발행일을 검사한다. 원문이 바뀐 요청의 유료 재시도와 검색 요약을 기사 본문으로 저장하는 경로를 차단하는 회귀 검증도 포함한다.

저장 검증은 이슈별 기사 소속, 전체 소속 기사 분석 예약과 최대 5개 발행을 확인한다. 실패 또는 빈 결과에서는 이전 이슈를 새 데이터인 것처럼 갱신하지 않는다. 공개 API에서는 현재 기사 버전이 없거나 출처가 부족한 이슈가 추천, 상세와 분석 상태에 나타나지 않는지 확인한다.

`v2-fan`으로 화면, 공개 API, 검색 provider와 저장 회귀 검증을 나누어 구현한 뒤 루트 작업에서 통합했다. 중단된 작업은 저장된 코드를 이어받아 검증을 완료했다. 미완료 구현 작업은 없다.

운영 DB 마이그레이션과 배포는 실행하지 않았다. 유료 검색 API를 호출하지 않았으며 운영 환경에서 이슈 3~5개가 실제 발행되었다고 확인하지 않았다. 운영 적용에는 `0022_issue_discovery_budget` 마이그레이션과 API 및 워커 배포, 유효한 검색 API 설정, 서로 다른 언론사 3곳 이상의 유효한 원문 수집 승인이 필요하다. 원문 접근 제한이나 출처 부족은 작업 결과의 거절 이유로 확인한다.

상세 로그는 Git에서 제외된 `output/topic-first-*` 파일에 보관한다.

## 신문 UI와 백엔드 통합 검증

2026-09-10에 `feat/topic-first-news`의 백엔드와 신문 UI를 함께 검증하고 `main`의 기존 변경을 통합했다. 이슈 발행은 독립 언론사 3곳 이상, 비교 화면에서의 기사 선택은 기존 API대로 2~4개를 유지한다.

- 분석 대기 중에도 확보한 모든 기사의 상세와 원문을 표시한다. 확보 수와 분석 완료 수를 구분하고 준비 상태를 주기적으로 다시 읽는다.
- 모바일 주소와 별도 출처 레코드를 같은 언론사로 묶는다. 기본 비교 선택 순서는 워커의 기사 ID 기준과 맞췄다.
- 분석이 끝난 뒤 선택 상태를 갱신하고, 발행 대상에서 제외된 이슈와 기사는 현재 이슈 목록으로 돌아가도록 안내한다.
- 새 수집 모듈 4개와 `0022_issue_discovery_budget` 및 공유 이미지용 신문 서체가 서버 배포 목록에서 누락된 문제를 수정했다.

브라우저의 실제 API 연결 검사는 memory backend를 사용했다. 공개 이슈의 기사 소속과 피드 범위, 비교 화면, 로그인과 회원 기능 및 제외된 콘텐츠의 복귀 경로를 확인했다. PC와 모바일 화면을 직접 확인했으며 배경은 `rgb(255, 255, 255)`이고 가로 넘침은 없었다. 분석 대기 화면은 실제 API 응답의 분석 상태를 브라우저에서 제어해 별도로 확인했다. 검증 이미지와 로그는 `output/playwright/integration-*`, `output/integration-*`에 있다.

운영 MariaDB에 변경을 가하지 않았고 유료 검색과 운영 배포도 실행하지 않았다. 이 검증은 실제 검색 결과의 발행이나 운영 배포 완료를 의미하지 않는다.

## 이슈 중심 제한 정책 조정

2026-09-10 사용자 승인에 따라 제한 수치는 유지하고 적용 순서를 변경했다.

- 7일 만료가 우선이며, 300개 초과 시 현재 발행 이슈의 유효한 기사 묶음을 먼저 보존한다. 나머지 공간에 이전 기사들의 날짜와 출처 비율을 적용한다. 실제 관계형 조회에서 승인 상태와 현재 버전도 검사한다.
- 탐색은 일일 예산의 60%와 기본 30개 분석 요청 중 오늘 아직 사용하지 않은 몫을 남기는 범위에서 진행한다. 이미 확보한 기사와 현재 검증할 기사의 보수적 분석 비용 추정이 더 크면 그만큼 추가로 보호한다. 남은 한도에 맞춰 이슈의 기사 수를 줄인다. 기존 99회 요청과 96개 분석 상태에서도 기사 4개짜리 이슈를 검증하고 분석 및 비교까지 총 107회 안에 처리하는 회귀 검증을 추가했다. 완료 응답의 재사용과 불명확한 유료 호출의 재시도 금지는 유지한다.
- 이슈당 기사 3~5개를 기본으로 하고, 별도 추가 맥락과 본문 근거가 있을 때만 최대 8개를 허용한다. 최대 5개 이슈가 확보되면 탐색을 종료한다.
- 새 이슈 다음에 유효한 기존 이슈를 배치해 총 5개까지 유지한다. 날짜가 지났거나 독립 언론사 3곳을 충족하지 못한 이슈는 제외한다. 기존 발행일과 최신 보도일 및 검수 날짜를 갱신하지 않으며 화면에도 두 날짜를 구분한다.
- 일일 스케줄러의 실행 주기 속성 누락을 수정했다. 워커가 60초마다 한국 날짜를 확인하고 날짜별 고유 키로 실제 작업은 하루 한 번만 생성한다. 실제 워커 스케줄러 루프를 거치는 회귀 검사를 추가했다.

서버 전체 415개, 프론트 95개, 서버 통합 18개와 실제 FastAPI memory backend 연결 브라우저 검사 8개가 통과했다. 기본 서버 검사 2개와 전용 MariaDB 환경을 요구하는 통합 검사 8개는 건너뛰었다. 정적 검사와 프로덕션 빌드 및 OpenAPI 계약 검증도 통과했다. PC 1440px과 모바일 390px에서 날짜 구분 표시와 가로 넘침이 없는 것을 확인했다. 증거는 `output/policy-*`와 `output/playwright/policy-dates-*`에 있다.

운영 배포, 유료 검색, 운영 DB 변경은 실행하지 않았다. 이번 정책 조정에는 추가 스키마 마이그레이션이 필요하지 않다.
