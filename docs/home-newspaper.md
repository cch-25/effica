# 홈 지면 구성

홈은 신문 제호, 주요 이슈의 제목과 원문 사진, 언론사별 기사 단을 유지한다. 서로 다른 사건의 기사를 한 목록이나 좌표 그래프에 섞지 않는다.

## 독자가 읽는 순서

1. 첫 면에서 머리기사의 제목, 원문 사진과 요약을 읽는다. 오른쪽 주요 이슈 목록에서 다른 지면으로 이동하거나 관련 쟁점의 상세를 열 수 있다.
2. 이슈 요약과 기사 수를 보고 보도 비교 화면으로 이동할 수 있다.
3. 같은 쟁점의 기사들을 언론사별로 나란히 읽는다. 발행 시각과 분석 요약을 표시한다.
4. 관련 쟁점이 있으면 펼쳐서 선택한다. 해당 지면의 요약, 사진, 비교 링크와 기사 목록이 함께 바뀐다.

머리기사는 넓은 본문과 좁은 이슈 목록으로 나눈다. 아래 보조 이슈는 두 단에 배치하고 기사 제목을 세로로 정리한다. 보조 이슈가 하나면 전체 폭을 사용한다. 760px 이하에서는 한 단으로 전환하며 주요 이슈 목록은 머리기사 뒤에 놓인다. 사진이 없거나 불러오지 못하면 해당 사진을 제외하고 텍스트로 구성한다.

## 분류와 정렬

공개 API는 `server/apps/api/app/domains/issues/coverage.py`에서 관련 쟁점을 분류하고 각 이슈에 `coverage_group_id`와 `coverage_group_title`을 내려준다. 공개 조건을 통과한 전체 이슈를 먼저 분류한 뒤 페이지를 나눈다. 목록과 상세 응답 모두 같은 묶음을 제공하며 MariaDB와 memory backend에 적용한다. DB 스키마 변경 없이 읽기 시점에 계산한다.

`home-edition.ts`는 서버가 정한 묶음을 사용한다. 홈에 불러오는 이슈는 최대 250개이며 광역 TOPIC, 오래된 이슈, 기사 또는 언론사가 3개 미만인 이슈는 제외한다. 서버가 별도 묶음으로 지정한 이슈를 제목만 보고 합치지 않는다. 해당 필드가 없는 구버전 API와 목업에 한해서 이전 제목 기반 분류를 유지한다.

관련성 규칙은 같은 주제와 7일 이내 기준일을 전제로 한다. 같은 기사에 연결된 이슈, 인사청문 맥락과 구체적인 제목 단어가 겹치는 이슈, 일반적인 제목에서 구체적인 단어가 2개 이상 겹치고 긴 제목의 단어 수 대비 40% 이상 일치하는 이슈를 연결한다. 일반적인 정치 용어와 직책은 공통 단어에서 제외한다. 연결된 쟁점들은 한 묶음으로 표시한다.

이는 제목과 기사 연결에 기반한 홈 탐색 규칙이다. 사건의 의미가 같다는 것을 보장하는 분류나 DB 병합이 아니다. 미묘한 쟁점의 과잉 묶음과 누락은 가능하다. 기존 issue ID와 기사 연결, 분석 점수는 바꾸지 않는다.

## 수집과 발행

후보 수집은 기존의 원문 출처 수와 중요도 정렬 후, 같은 관련성 규칙으로 묶인 후보들을 번갈아 탐색한다. 다른 사건을 먼저 확인한 뒤 관련 쟁점을 추가한다. 새 후보 검색이나 분류용 LLM 호출을 추가하지 않으며 예산 한도와 기사 분석 비용 예약을 그대로 적용한다. 출처가 3곳 미만인 후보의 공개 기준도 낮추지 않는다.

저장 단계에서도 다양한 사건을 우선한다. 새로 발행한 이슈가 5개 미만이면 유효한 이전 이슈를 보충하되, 새 지면에 없는 사건부터 유지한다. 이때 이전 이슈의 발행 시각과 버전은 갱신하지 않는다. 하루 발행 한도는 여전히 개별 이슈 최대 5개이므로 홈의 묶음 수는 5개보다 적을 수 있다. 수집 후보 자체가 한 사건에 집중되면 이 규칙만으로 다양성을 보장할 수 없다.

기존 이슈를 갱신할 때는 주제와 고유한 `issue_key`로 만든 식별자를 사용한다. 기사 한 건이 겹친다는 이유로 다른 이슈의 식별자를 가져와 기사 구성을 덮어쓰던 경로는 제거했다. 검색 모델이 같은 사건의 키를 다르게 만들면 별도 이슈가 생길 수 있으므로 홈 탐색용 묶음과 이슈 식별을 구분한다.

## 지면 표시

관련 쟁점을 먼저 묶고 나서 편집 우선순위에 따라 최대 5개 묶음을 표시한다. 같은 우선순위에서는 언론사 수, 기사 수, 최근 갱신 시각 순이다. 각 묶음의 첫 화면은 비교 준비를 마친 쟁점을 우선한다.

기사 목록은 선택한 이슈의 `articleIds`에 포함된 기사만 사용한다. 발행 시각 내림차순으로 정렬하고 같은 언론사의 최신 기사 1건씩 최대 3건을 먼저 보여준다. 더 보기에서는 불러온 해당 쟁점의 기사 전체를 펼친다. 추가 API 페이지가 있으면 상세 목록으로 연결한다. 표시 수와 전체 기사 수를 구별한다.

## 검증

- `.ops/run.sh test-web`: 제목 관련성, 기사 범위, 언론사 중복과 최신 기사 선택을 검사한다.
- `.ops/run.sh test`: 서버 분류, 페이지 경계를 넘는 묶음 일관성, 이슈 키 보존, 다양한 후보 우선 탐색, 이전 이슈 보충과 기존 예산 제약을 검사한다. 외부 LLM 호출은 대체 응답으로 검증한다.
- `.ops/run.sh openapi`: 실행 가능한 API와 프론트의 생성 계약이 일치하는지 검사한다.
- `.ops/run.sh test-browser e2e --grep 'readers can choose|selected unready|empty edition' --workers=1`: 이슈 목차 이동, 관련 쟁점 전환, 더 보기, 준비 상태, 빈 지면을 검사한다. 1440, 1024, 768, 390, 320px 화면에서 가로 넘침을 확인한다.
- 머신별 `.ops/run.sh home-audit [URL] [너비목록]`은 `client/scripts/home-audit.mjs`를 실행한다. 실제 화면의 쟁점 전환 결과를 공개 API의 기사 ID와 대조하고 접근성 검사 및 화면 캡처를 `output/playwright/home-newspaper/`에 기록한다.

목업 검사는 운영 데이터의 수집 품질을 증명하지 않는다. 서버 코드 변경은 배포 후 API 조회와 다음 수집부터 적용되며 기존 운영 DB를 수동 병합하거나 새 수집을 즉시 실행하지 않는다.
